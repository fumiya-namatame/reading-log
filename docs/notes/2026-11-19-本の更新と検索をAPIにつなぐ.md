## 学んだこと

### fetch は 4xx / 5xx でも例外にならない

`fetch` が例外を投げるのは通信そのものに失敗したときだけ。404 や 500 が返っても成功扱いになるので、`response.ok` を自分で確認して例外を投げる。

- 使った場所: `frontend/src/api/bookApi.ts` の `fetchBooks` / `updateBook`
- 削除（`deleteBook`）では 404 を成功扱いにしたが、更新（`updateBook`）では 404 を失敗として扱う。「もう無いものを消す」は目的を果たしているが、「無いものを更新する」は果たせないため

### URL に値を埋め込むときはエスケープする

- パスの一部（ID）には `encodeURIComponent` を使う（`/api/books/a%2Fb%3Fc`）
- クエリ文字列（検索語）には `URLSearchParams` を使う。`&` `=` `#` などもエスケープされる
- `URLSearchParams` は空白を `+` に変える。Spring が `+` を空白として受け取ることを、実際にサーバーを起動して確かめた

### 未入力は画面では空文字、API では null

画面（フォーム）では未入力を `''` で扱い、API には `null` で送る。受け取った `null` は `''` に戻す。変換は `toRequest` / `toBook` にまとめてある（`frontend/src/api/bookApi.ts`）。

### await のあとは「今の」一覧を使う

通信を待っている間に一覧が取り直されることがある。そのため、待つ前の一覧ではなく、待ったあとの `books.value` を使って置き換える。

```ts
// frontend/src/composables/useBooks.ts（editBook）
const updatedBook = await updateBook(id, input)
books.value = books.value.map((book) => (book.id === id ? updatedBook : book))
```

### 古い通信の結果で上書きしない

検索を続けて行うと、先に送った検索の結果が後から届き、新しい結果を上書きすることがある。取得のたびに番号を振り、最後に始めた取得の結果だけを使うようにした。古い取得が失敗しても、エラーは出さない。

```ts
// frontend/src/composables/useBooks.ts（loadBookList）
const loadId = ++latestLoadId
const fetchedBooks = await fetchBooks(keyword)
if (loadId !== latestLoadId) return
```

### デバウンス

1 文字打つたびに検索すると通信が多くなるので、入力が 300 ミリ秒止まってから検索する（`frontend/src/components/BookSearch.vue`）。

- 入力のたびに `clearTimeout` で前のタイマーを消し、新しいタイマーを始める
- 前回と同じ条件（末尾に空白を足しただけなど）なら検索しない
- 画面から消えるときは、`onBeforeUnmount` でタイマーを止める
- `v-model` は日本語の変換中は値を更新しないので、変換が確定するまで検索は始まらない

### 保存中は二度押しを止める

`isSaving` が true の間は、送信ボタンを押せなくする。編集の「キャンセル」も押せなくした。保存中にキャンセルできると、画面では編集をやめたのに更新だけが反映される、というずれが起きるため。

### 1 つのフォームを追加と編集で使い回す

`BookForm` に `editingBook` を渡すと、その内容を入力欄に入れて「更新」用の表示にする。`watch` に `immediate: true` を付けると、最初から渡された場合にも反映される。`null` に戻ると入力欄を空にする。

### コンポーネントには「場面」ではなく「中身」を渡す

`BookList` には「検索中かどうか」ではなく、0 件のときの文言（`emptyMessage`）そのものを渡すようにした。どの場面で何と表示するかは `App` が決め、`BookList` は検索のことを知らずに済む。

### テストの工夫

- `createDeferred`（resolve を呼ぶまで終わらない Promise）で、「通信の途中」の状態を確かめる
- `vi.useFakeTimers()` で、デバウンスの待ち時間を実際には待たずに進める
- 仕組みを一時的に外して、テストが失敗することを確かめた。古い結果を捨てる処理を外すと、3 件が失敗した。テストがきちんと見分けられていることが分かる

## つまずいた点・疑問

- **ボタンを `find('button')` で探すテストが壊れた**
  - `BookListItem` に「編集」ボタンを先頭に足したら、最初のボタンを削除ボタンとみなしていた `BookList` のテストが失敗した
  - `.book-item__delete` のように、クラス名で指定するよう直した
- **検索で一覧から外れただけで編集が止まる問題**
  - 「編集中の本が一覧から消えたら編集をやめる」作りだったので、検索で絞り込むと、書きかけの入力が消えてしまう
  - 「削除に成功したときだけ編集をやめる」（`handleDelete`）に直した
- **`v-if` と `v-else` の間に要素を入れてしまった**
  - `BookSearch` を「読み込み中…」（`v-if`）と `BookList`（`v-else`）の間に置いて、組み合わせが崩れた。`v-if` の前に移して直した
- **サーバーの起動に失敗した**
  - ログの出力先フォルダがまだなかったのが原因。フォルダを作ってから起動し直した
- **残っている気になる点**
  - 追加フォームに入力している途中で「編集」を押すと、その入力が上書きされる
  - 検索で絞り込んでいる間に追加・編集した本は、条件に合わなくても一覧に出たままになる
  - 検索のたびに一覧が一瞬「読み込み中…」になる（今は気にならない程度）
