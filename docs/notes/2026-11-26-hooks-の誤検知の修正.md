# hooks の誤検知の修正

## 今回のテーマ・やったこと

- PR を作るときに、自分たちの `block-dangerous.sh` が `gh pr create` を止めた（誤検知）
- 判定方法を「コマンド文字列全体」から「区切った 1 つ 1 つのコマンドの先頭」に変えて直した
- hook のテストスクリプト `.claude/hooks/test-block-dangerous.sh` を追加した（44 件すべて成功）

## 学んだこと

### 文字列全体を正規表現で見ると、引数の中の文字にも反応する

最初の `block-dangerous.sh` は、Bash のコマンド文字列全体に `rm ... -r` と `.` や `/` などがあるかを正規表現で調べていた。
そのため、実行されない文字（PR 本文やコミットメッセージ）の中に `rm -rf .` と書いてあるだけで拒否した。

- PR 本文に「`rm -rf .` → 拒否」と書いた `gh pr create --body "..."` が止められた
- 強制 push や `git reset --hard` の判定も同じで、`git commit -m "git push --force を禁止"` も止めてしまう状態だった

### コマンドに区切ってから、先頭を見る

`.claude/hooks/block-dangerous.sh` を、次の順番で判定するように直した。

1. ヒアドキュメント（`<<'EOF'` 〜 `EOF`）の本文を消す
2. 引用符の中の `;` や `|` などを空白にしてから、引用符を外す
   → `-m "...; rm -rf ."` は、区切られずに `git` コマンドの引数として残る
3. `&&`、`||`、`;`、`|`、改行、`$(` などで、1 行に 1 コマンドずつに分ける
4. 各コマンドの前に付く `sudo`、`xargs`、`bash -c` などを外す
5. 先頭が `rm`（`git`）のコマンドだけを判定する

また、拒否（deny）の判定を確認（ask）より優先するようにした（例: `git reset --hard && rm -rf .` は deny）。

### 文字列で推測する方式の限界

完全には防げない。例えば `git -C dir push --force` や、変数に入れたコマンドの実行は見逃す。
hooks は最後の守りではなく、「よくあるミスを防ぐ仕組み」として考える。

### hook のテストを用意しておく

`.claude/hooks/test-block-dangerous.sh` は、偽の入力 JSON を hook に流して、結果が deny / ask / allow のどれかを確かめる。

- 止めるべきもの: `rm -rf .`、`sudo rm -rf /`、`bash -c "rm -rf ."`、`git push -f origin main` など
- 止めてはいけないもの: コミットメッセージ、PR 本文、`grep -rn "rm -rf" ...`、`rm -rf frontend/node_modules` など
- 実行: `bash .claude/hooks/test-block-dangerous.sh`
- テストの中の「危ないコマンド」は文字列のデータなので、テストスクリプトを実行しても hook には止められない

単体テストのあとで、実際の Claude の操作でも確かめた。
`echo "説明: rm -rf . → 拒否; ..."` は実行され、`cd /tmp && rm -rf .` はこれまでどおり拒否された。

### 引数に危ない文字が入るときの回避策

修正の前は、PR 本文を Write ツールでファイルに書き出し、`gh pr create --body-file <ファイル>` で渡して PR を作った。
`block-dangerous.sh` は Write ツールでは `.env` しか見ないので、ファイルへの書き出しは止められない。

### Claude Code は起動したときの環境変数を使い続ける

- `~/.zshrc` の `JAVA_HOME` は Java 25 になっていたが、この Claude Code の `JAVA_HOME` は openjdk@17 のままだった
- `~/.zshrc` を変える前から開いていたターミナルのタブ（または IDE）から起動したためと考えられる
- Stop フックも Claude Code と同じ環境で動くので、このままだと backend を変えたときに `./mvnw test` が失敗する
- `JAVA_HOME` を Java 25 にして `./mvnw -q test` を実行すると、成功した（終了コード 0）

### zsh では `PIPESTATUS` が使えない

`./mvnw test | tail` の終了コードを `${PIPESTATUS[0]}` で取ろうとしたら空だった。`PIPESTATUS` は bash の変数で、zsh では使えない。
パイプを使わずに実行し、`$?` で確かめた。
